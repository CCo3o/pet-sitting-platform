# 多角色智能工作台

登录后 `/workspace` 根据认证身份进入宠物照护助手、服务执行助手或平台运营助手。顶部待办直接查询数据库，不调用模型；快捷提问填入输入框，由用户发送。原业务页面仍可从导航进入。

## 演示

1. 主人登录，提出预约需求，补齐宠物、地址、日期、预算，选择实际返回时段，核实预约草稿后确认，在订单页面查看。
2. 喂养员登录，点击“查询我的订单，整理今天的服务安排”。演示记录时，先把实际订单按正常流程接单、模拟付款并开始服务，然后说明订单和实际完成的喂养情况。助手读取订单与记录，生成履约草稿。编辑核实后点击“核实并确认保存”，到订单详情查看记录。
3. 主人或喂养员对订单提交测试投诉。管理员登录，查询待处理投诉，选择投诉让助手分析订单及履约证据并生成处理建议。人工核实、修改建议后确认，投诉变为已处理。需要补充证据时先保留草稿，不要确认结案。

## 实现边界

- 共享 DeepSeek 接口，按角色提供独立提示词和工具集合；这是多角色工具型 Agent，不是多个模型互相协作。
- 主人沿用预约工具；喂养员只读本人订单；管理员读取运营统计、待审核资料、投诉及关联记录。
- 模型工具只能保存草稿。履约记录与投诉结案使用独立确认接口，后端重新校验身份、对象和状态。
- 操作草稿有效期15分钟；确认事务锁定草稿并记录结果ID，重复确认返回原结果。会话按用户隔离。
- 每轮生成草稿前必须重新读取目标详情。服务事实需用户提供并人工核实，模型不能证明现实中是否已经喂养。
- 本轮验证为本地协议测试和浏览器验证。新角色真实 DeepSeek 效果需要带密钥启动后实际验收；既有主人评测不代表新角色评测结果。

## 本地启动

原后端终端停止旧进程，再执行 `.\scripts\start-agent.cmd` 并按提示输入密钥。前端在另一终端执行 `.\scripts\frontend.cmd dev`。打开 http://127.0.0.1:5173/ 后分别登录三个角色。
